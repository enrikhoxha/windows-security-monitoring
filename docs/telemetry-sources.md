# Telemetry Sources

This repository focuses on a small set of high-value telemetry sources that support practical Windows security monitoring and investigation.

## Sysmon

Sysmon provides enhanced endpoint telemetry beyond standard Windows logging.

Current focus areas include:

- **Event ID 1 - Process Create**
  - Process execution
  - Parent/child relationships
  - Command-line context

- **Event ID 3 - Network Connect**
  - Outbound and inbound connection context
  - Destination addresses and ports
  - Process-to-network relationships

- **Event ID 22 - DNS Query**
  - DNS requests generated by endpoint processes
  - Process and queried-domain context

These events are especially useful when correlating endpoint behavior with network or firewall telemetry.

## Windows Security Log

Security logs provide authentication and access-related visibility, including:

- Successful and failed logons
- Logon types
- Account activity
- Security-relevant access events

Authentication events are reviewed alongside endpoint and network activity where possible.

## Microsoft Defender Operational Log

Defender telemetry is used to validate endpoint protection state and investigate security-related events generated by Microsoft Defender.

## PowerShell Operational Log

PowerShell logging provides additional context for administrative and scripted activity, especially during investigations involving command execution or automation.

## Windows System and Supporting Logs

System logs provide operational context for:

- Boot and shutdown events
- Service activity
- System state changes
- Troubleshooting and event correlation

## Wazuh Alerts and Events

Wazuh centralizes and analyzes telemetry collected from monitored systems.

The platform is used for:

- Event collection
- Rule-based alerting
- Detection validation
- Search and investigation
- Cross-source correlation

## Firewall and Network Telemetry

Network telemetry provides context that can be compared with endpoint events, including:

- Source and destination addresses
- Source and destination ports
- Protocol
- Connection activity
- Rule or policy context

Public examples are sanitized to avoid exposing internal addressing or organization-specific configuration.

## Correlation Approach

A useful investigation often combines multiple sources. For example:

```text
Sysmon Process Event
        +
Sysmon Network Event
        +
DNS Query
        +
Firewall Connection Log
        =
Stronger investigation context
```

The goal is not simply to collect logs, but to use multiple sources to understand what occurred and whether activity is expected or suspicious.
