# Investigation Walkthrough: PowerShell With Follow-on Network Activity

## Scenario

A Windows endpoint generates a Sysmon Process Create event showing PowerShell launched with an encoded command. Within the same time window, the endpoint also generates DNS and network-connection telemetry.

This walkthrough shows how to correlate those signals without relying on a single event in isolation.

## Initial Signal

**Source:** Sysmon Event ID 1 — Process Create

Sanitized example:

```text
Image: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
CommandLine: powershell.exe -EncodedCommand <redacted>
ParentImage: C:\Windows\System32\cmd.exe
User: DOMAIN\user
```

The encoded argument is a reason to investigate, not proof of malicious activity.

## Step 1 — Review the Process Context

Validate:

- endpoint hostname and role
- user account
- process image path
- parent process
- command line
- process creation time
- whether PowerShell use is expected on the host

Questions to answer:

- Was the user performing an approved administrative task?
- Is the parent process normal for this workflow?
- Does the process tree show an unusual launch chain?

## Step 2 — Decode and Review the Command

If authorized to do so, decode the PowerShell payload in an isolated analysis workflow and review it as text before executing anything.

Look for behaviors such as:

- downloads or web requests
- credential access
- persistence changes
- Defender exclusions
- encoded or obfuscated follow-on commands
- new processes
- file creation
- registry changes

Never execute an unknown decoded payload simply to determine what it does.

## Step 3 — Correlate DNS Activity

**Source:** Sysmon Event ID 22 — DNS Query

Search a narrow time window around the process creation event and identify DNS queries generated by the same endpoint.

Sanitized example:

```text
Process: powershell.exe
QueryName: example.invalid
EventID: 22
```

Review whether the queried domain is expected for the organization, software, or administrative task.

## Step 4 — Correlate Network Connections

**Source:** Sysmon Event ID 3 — Network Connect

Search for outbound connections from PowerShell or related child processes.

Sanitized example:

```text
Image: powershell.exe
DestinationIp: 203.0.113.25
DestinationPort: 443
Protocol: tcp
EventID: 3
```

The example address is from documentation-only address space and does not represent a real system.

Review:

- destination reputation and ownership using approved tools
- destination port and protocol
- whether the connection followed the DNS query
- other processes connecting to the same destination
- firewall telemetry for the same source/destination pair

## Step 5 — Check Additional Windows Telemetry

Correlate the event with:

- Windows Security logon events
- Microsoft Defender Operational events
- PowerShell Operational logging, when enabled
- additional Wazuh alerts
- endpoint changes around the same timestamp

This helps determine whether the process was isolated activity or part of a larger sequence.

## Step 6 — Determine Disposition

### Likely Benign

Possible indicators:

- known administrator
- approved maintenance window
- expected parent process
- known script or management platform
- expected network destination
- no suspicious follow-on activity

Document the reason and consider tuning only when the legitimate pattern is stable and specific.

### Requires Escalation

Escalate when indicators include:

- unknown or unexpected user context
- suspicious parent/child process chain
- unknown encoded content
- unexpected external network connections
- security-control modification
- credential-related behavior
- persistence attempts
- multiple correlated alerts

## Example Investigation Timeline

| Time | Source | Observation |
| --- | --- | --- |
| 10:14:02 | Sysmon ID 1 | PowerShell starts with encoded command |
| 10:14:04 | Sysmon ID 22 | PowerShell performs DNS lookup |
| 10:14:05 | Sysmon ID 3 | PowerShell opens outbound TCP/443 connection |
| 10:14:07 | Wazuh | Encoded PowerShell detection alert generated |
| 10:15+ | Analyst | Process, DNS, network, and endpoint context reviewed |

## Analyst Takeaway

The key lesson is correlation. An encoded PowerShell command alone can have legitimate explanations. Process ancestry, DNS activity, network connections, user context, Defender events, and firewall telemetry provide the evidence needed to make a defensible determination.
